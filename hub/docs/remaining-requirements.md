# Remaining work — cloud activation and hosted verification only

The current application inventory, guides, security boundaries, local evidence and deliberate provider limitations are in [product-handbook.md](product-handbook.md). Older sprint documents are historical evidence, not a current missing-feature checklist.

No provider credentials are requested by the development assignment. Do not create resources or spend money to complete local tests.

1. Securely supply authorized provider account access and runtime secrets. Actual accounts/plan/roles/quota/issuer/entitlements remain unverified. Never share secret values in chat/GitHub.
2. Approve exact costs and isolated cloud resources/network/recovery configuration. Do not repurpose StackLTR or upgrade its existing organization as a side effect.
3. Provision dedicated database, non-owner runtime role, separate owner, backups/keys and OIDC client/MFA. Apply the five forward migrations and provision synthetic owner/customer fixtures only after hosted-change approval.
4. Configure dedicated Vercel Preview bindings and all-URL protection; approve exact commit/project deployment and exact project-returned Cloudflare DNS values. Preserve the public site, main and production hostname.
5. Run mandatory real hosted authentication/security, managed PostgreSQL/pooling, recovery, connector, worker and Alpha/Bravo acceptance tests. Local contract fixtures are not live verification; manual/unsupported CMS features remain accurately labelled.
6. Review final evidence, costs, remaining trust limits and obtain release approval. No merge or production deployment is authorized.

Existing live marketing source disclosure remains documented outside the Hub; no public-site remediation occurred. The draft stack's internal-file exclusions still require hosted all-hostname verification before acceptance.
