### Free alternative that preserves the existing OIDC flow

**ZITADEL Cloud Free is the preferred new-provider candidate**, subject to account approval and real-flow verification. Its [pricing](https://zitadel.com/pricing) lists **$0, all security features, 100 daily active users, unlimited stored users/organizations and three external identity providers**. [Detailed pricing](https://zitadel.com/pricing/detail) lists a generated domain and one administrator on Free. The [OIDC endpoint contract](https://zitadel.com/docs/apis/openidoauth/endpoints) documents confidential `client_secret_post`, code flow and S256; the [claims contract](https://zitadel.com/docs/apis/openidoauth/claims) explicitly documents `amr: ["pwd", "mfa"]` and `azp`. This directly addresses the previously unverified free-MFA option without changing the Hub's security checks. Its [general service terms](https://zitadel.com/docs/legal/terms-of-service) did not reveal a Vercel-Hobby-style personal-only restriction; confirm actual signup terms/Free eligibility, quota behavior and any internal-staff licensing before registration. Pricing is not an account entitlement.

Other options checked: [Descope Free](https://www.descope.com/pricing) advertises MFA and one federated OIDC app, 7,500 MAU and ten monthly active tenants, with no overages (upgrade required at limits). It is described for hobbyists/solo builders; commercial eligibility and the precise signed ID-token AMR/token-auth contract remain unverified, so it is a fallback, not an asserted drop-in. Logto and authentik documentation requests returned 403; no unverified plan claim is made. Self-hosting an IdP adds patching, hosting and recovery duties and is not a verified cheaper substitute here.

**Decision — COMPLETE recommendation; NEEDS APPROVAL tenant setup:** keep the current OIDC implementation, MFA claim check, secure sessions and Hub-local authorization. Prefer an existing licensed compatible MFA IdP if its verified incremental cost is $0; otherwise use ZITADEL Cloud Free after approval. Auth0 Free and Neon Managed Auth remain unsuitable for the documented mandatory MFA requirement. No identity tenant/application was created; no ZITADEL issuer is known. Do not invent an issuer or infer that documentation proves real MFA.

Prepared client registration (`staging/oidc-client-profile.example.json`): dedicated confidential Web application, authorization code + S256, token auth `client_secret_post`, supported asymmetric signatures, exact callback `https://hub-preview.crumbyte.com/auth/callback`, exact origin `https://hub-preview.crumbyte.com`, no wildcard. OIDC scopes stay `openid email profile`. **Required ZITADEL setting: enable `id_token_userinfo_assertion` (Console: “User Info inside ID Token”).** Its endpoint documentation says code flows issuing an access token otherwise omit email/profile claims from the ID token. The Hub deliberately reads signed ID-token claims and requires `email_verified=true` for first-time binding; it does not call UserInfo. Verify the actual token has both email and verified status, rather than weakening that check or rewriting login. Use the provider-generated domain; no paid custom identity domain needed. Restrict staff enrollment, disable public self-registration for Hub access and enforce MFA for every permitted Hub login with approved TOTP/WebAuthn and recovery controls. Local verified-token `amr:mfa` enforcement remains unchanged. Do not label a single email code/passkey or a provider trial as satisfying this without actual signed claim/policy evidence.

After approved setup, use the actual issuer's discovery with `validateOidcMetadata`; it must support same-origin HTTPS endpoints, S256, `client_secret_post` and approved asymmetric signing. Securely inject the issuer/client ID and matching independent staging pins; client secret only in Preview settings. Test a real signed ID token including audience/azp, verified email, nonce and `amr:mfa`, and deny missing-MFA/unprovisioned/disabled staff. Proof must include an actual MFA challenge, not imported cookies or a synthetic claim. The app's `/logout` revokes its own session; upstream SSO logout is not implemented. A logout allowlist, if needed, uses `https://hub-preview.crumbyte.com/login`. All real-provider checks remain unrun pending access/setup authorization.
